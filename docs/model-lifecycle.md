# ETA Model Lifecycle Management (SCRUM-1228)

This guide details the durable S3 artifact storage, SHA-256 integrity verification, authorized candidate promotion, safe atomic activation, and rollback procedures for the SpotQ ETA prediction microservice.

---

## 1. Overview and Architecture

SCRUM-1228 connects candidate artifacts generated by the offline training pipeline (SCRUM-1197) to live inference serving. It provides an auditable, controlled model promotion workflow with zero downtime and instant recovery.

```text
 ┌────────────────────────────────────────────────────────┐
 │ 1. Training Pipeline (SCRUM-1197)                     │
 │    - Evaluates chronological holdout                  │
 │    - Computes SHA-256 digest                          │
 │    - Registers candidate in S3 / local registry       │
 └──────────────────────────┬─────────────────────────────┘
                            │
                            ▼
 ┌────────────────────────────────────────────────────────┐
 │ 2. Versioned S3 Storage & Manifest                    │
 │    s3://<bucket>/models/<version>/eta_model.json       │
 │    s3://<bucket>/models/<version>/manifest.json        │
 └──────────────────────────┬─────────────────────────────┘
                            │
                            ▼ Operator calls:
 ┌────────────────────────────────────────────────────────┐
 │ 3. Authorized Promotion Endpoint                       │
 │    POST /api/v1/eta/admin/promote-candidate            │
 │    Header: X-Admin-Key                                 │
 │    Body: { "model_version": "...", "approver_id": ".." }│
 └─────────────┬──────────────────────────┬───────────────┘
               │                          │
        Valid? │                          │ Corrupt / Incompatible?
               ▼                          ▼
 ┌───────────────────────────┐   ┌──────────────────────────┐
 │ 4. Atomic In-Memory Swap  │   │ Safe Failure             │
 │    - Active model updated │   │ - Active model preserved │
 │    - Previous model kept  │   │ - HTTP 422/503 returned  │
 │      in memory for        │   │ - Failure metric logged  │
 │      instant rollback     │   └──────────────────────────┘
 └─────────────┬─────────────┘
               │
               ▼
 ┌────────────────────────────────────────────────────────┐
 │ 5. Controlled Rollback Endpoint                        │
 │    POST /api/v1/eta/admin/rollback-model               │
 │    - Restores previous approved model in sub-millisecond│
 └────────────────────────────────────────────────────────┘
```

## 2. S3 Artifact Storage & SHA-256 Integrity Verification

Model artifacts are stored with version-specific references and strict integrity guarantees:
- **Unique Versioning:** S3 keys follow `{S3_ARTIFACT_PREFIX}/{model_version}/eta_model.json`.
- **Integrity Digest:** A SHA-256 hexadecimal digest is computed using chunked binary streaming before upload and verified on download.
- **Corruption Prevention:** If an artifact is truncated, incomplete, or modified in transit, the SHA-256 check fails, the corrupt file is deleted immediately, and promotion is aborted (`HTTP 422`).
- **Environment Agnostic:** Uses AWS S3 when credentials/bucket are configured, and seamlessly falls back to local staging storage (`S3_LOCAL_STORAGE_DIR`) in offline development and test environments.
- **Auto-Bootstrapping on Startup:** On initial service boot (such as a fresh repository clone without local model binaries), the service automatically queries S3, retrieves the latest verified model, validates its checksum and feature schema, and activates it.

### Environment Configuration (Infisical / Runtime)

| Variable | Description | Default |
| :--- | :--- | :--- |
| `AWS_S3_BUCKET` / `S3_BUCKET_NAME` | S3 bucket storing versioned artifacts | `spotq-restaurant-files` |
| `AWS_REGION` / `S3_REGION` | AWS Region | `ap-south-1` |
| `S3_ARTIFACT_PREFIX` | S3 key prefix for versioned models | `ml-models/eta` |
| `S3_ENDPOINT_URL` | Optional custom endpoint (MinIO / LocalStack) | `None` |
| `AWS_ACCESS_KEY_ID` | AWS IAM access key (optional with IAM roles) | Injected via Infisical |

| `ETA_MODEL_ADMIN_KEY` | Minimum 32-character secret for admin operations | Injected via Infisical |

Two end-to-end integration scripts are available for testing:

## 3. Pre-Promotion Candidate Validation Gates

Before a candidate is permitted to activate, the service downloads the artifact to an isolated staging directory and executes strict pre-promotion validation:
1. **File Retrieval & Existence:** Artifact must exist in storage and download cleanly.
2. **SHA-256 Checksum:** Downloaded file digest must match registered manifest.
3. **Isolated Booster Load:** Loads the candidate into an isolated XGBoost booster instance.
4. **Canonical 6-Feature Schema:** Must match the serving contract:
   `['party_size', 'total_people_ahead', 'hour_of_day', 'day_of_week', 'is_weekend', 'historical_average_wait']`.
5. **Environment Provenance Policy:** Models trained on `synthetic` data are strictly rejected in `production` environments (`ENVIRONMENT=production`).
6. **Smoke Test Prediction:** Verifies that a sample inference vector produces a valid finite numerical prediction.

If any check fails, the active production model is preserved with zero disruption.

## 4. Operator Runbook

### Inspecting Model Status
```bash
curl -s http://127.0.0.1:8000/api/v1/eta/admin/model-status \
  -H "X-Admin-Key: <your-32-char-admin-key>" | jq
```

### Listing Registered Candidates
```bash
curl -s http://127.0.0.1:8000/api/v1/eta/admin/candidates \
  -H "X-Admin-Key: <your-32-char-admin-key>" | jq
```

### Promoting a Candidate Model
```bash
curl -s -X POST http://127.0.0.1:8000/api/v1/eta/admin/promote-candidate \
  -H "Content-Type: application/json" \
  -H "X-Admin-Key: <your-32-char-admin-key>" \
  -d '{
    "model_version": "candidate-20261031",
    "approver_id": "senior_ml_engineer",
    "notes": "Validated holdout MAE 2.1m exceeds baseline"
  }' | jq
```

### Rolling Back to Previous Model
If an issue occurs in production after promoting a model, restore the previous known-good model instantly:
```bash
curl -s -X POST http://127.0.0.1:8000/api/v1/eta/admin/rollback-model \
  -H "X-Admin-Key: <your-32-char-admin-key>" | jq
```

## 5. Deployment Topology & Multi-Replica Safety

- **Atomic Memory Replacement:** Within a single Python process, model activation is guarded by an `RLock`. Incoming prediction requests either read the active snapshot or the new snapshot—they never read a half-loaded model.
- **Multi-Replica Deployment:** In Kubernetes or multi-container deployments, operator promotion requests should be broadcast to all replicas or executed as part of rolling deployment orchestration.
- **Rollback Availability:** The previous booster and manifest remain preserved in memory, enabling sub-millisecond rollback without network roundtrips.
